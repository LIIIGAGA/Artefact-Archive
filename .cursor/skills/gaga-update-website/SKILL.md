# Gaga-UpdateWebsite

## 目标

根据用户提供的截图、描述文字和当前仓库中新添加的内容，准确完成网站更新，并在验证后通过 GitHub Desktop 推送到远程仓库。

## 工作流程

### 1. 收集输入

当用户说“帮我更新网站”时启用本技能。

- 接收用户发送的网站截图和描述文字。
- 如果截图或描述尚未提供，请用户补充后再继续。
- 将截图视为视觉与布局依据，将描述文字视为内容和行为要求；两者冲突时指出冲突并请用户决定。

### 2. 调查仓库

只做读取和分析，不立即修改文件。

- 检查仓库状态，识别已有的未提交改动，避免覆盖用户的工作。
- 查找与截图和描述对应的 HTML 页面、相关样式、脚本及资源引用。
- 检查仓库中新添加或未跟踪的文件，重点关注图片、视频、文档及其他内容素材。
- 通过文件名、内容、尺寸、预览和页面结构，将新素材与目标页面区域进行匹配。
- 如存在多个合理目标或无法可靠确定映射，明确列出候选项，不自行猜测。

### 3. 修改前确认

在任何网站文件修改之前，向用户提交一次简洁的变更确认，至少包括：

- 将修改的页面和具体区域。
- 将新增、替换或删除的内容。
- 将使用的新素材文件及其对应位置。
- 预计涉及的文件清单。
- 任何不确定项、视觉差异或潜在影响。

明确询问用户是否确认按此方案更改。未收到肯定确认前，不修改网站文件、不提交、不推送。

如果用户要求调整方案，更新变更清单并再次确认。

### 4. 实施更新

仅在用户确认后开始。

- 只修改已确认范围内的内容。
- 遵循现有 HTML、CSS 和 JavaScript 的结构、命名与格式风格。
- 正确引用已匹配的新素材，不制造不必要的重复文件。
- 保留无关的用户改动；不得重置、覆盖或清理未授权内容。
- 如实施中发现会实质改变确认方案的新问题，暂停并再次向用户确认。

### 5. 验证结果

- 检查所有修改后的链接、资源路径、文字与页面结构。
- 使用项目已有的本地预览或测试方式打开页面，核对截图所示的目标区域。
- 进行适合项目的测试或静态检查。
- 检查最终差异，确认只有预期文件发生变化，且新素材已被正确纳入。
- 若验证失败，修复后重新验证；不要推送未验证的更改。

### 6. 使用 GitHub Desktop 推送

验证通过后：

- 打开 GitHub Desktop，并选择当前仓库。
- 在 GitHub Desktop 中复核变更文件，确保没有夹带无关改动或敏感信息。
- 使用概括本次网站更新的清晰提交信息创建提交。
- 通过 GitHub Desktop 将当前分支推送到远程仓库。
- 不要用命令行推送来替代 GitHub Desktop；如果 GitHub Desktop 无法打开、仓库未配置远程、需要登录、出现冲突或推送失败，暂停并向用户说明具体阻碍，不宣称已完成。

### 7. 完成汇报

只有确认远程推送成功后，才告诉用户修改完成。汇报应包含：

- 已更新的页面与主要内容。
- 验证结果。
- 提交信息和推送的分支。
- 如可获取，提供提交标识。

## 安全边界

- 用户的确认仅授权所列的网站更新与相应提交、推送，不授权删除或改写其他历史。
- 不执行强制推送、历史重写、硬重置或大范围删除。
- 不将密钥、凭据、本地配置或无关文件纳入提交。
- 若当前分支包含无法与本次更新安全分离的既有改动，先向用户说明并请求处理方式。
